## Scope and architecture

The latest user change explicitly authorizes Screenshot, Clipboard, Git, Eye Care and AI Limits; it supersedes the historical monitor-only/developer-feature exclusions for these modules only. No messaging, handoff, cloud, credentials, helper or package work. Preserve compact monitor toggle order and existing rendering/resource rules. No Git mutations during development. All five tools start disabled for existing installs; Git/AI remain disabled by default in all installs. Enabling Clipboard explicitly consents to future clipboard events, never imports the existing clipboard implicitly. Display effects and input injection are exercised only by mock executors during automated verification.

Portable Core owns tool identifiers, settings/order, capabilities, badge snapshots, history/expiry/secret policy, sanitized Git porcelain parsing, screenshot edit/redaction models, comfort scheduling and usage block/calibration math. Shell owns IToolModule (id/icon/badge/popup/dashboard/settings/hotkeys/Start/Stop), lightweight views and shared interaction components. Windows owns mockable capture/clipboard/input/hotkey/display/process/file adapters. Composition root alone wires modules. No module references another tool.

Use existing approved .NET/Windows SDK references and installed Segoe icon fonts. Any newly required dependency stops that affected feature for approval. Every enabled module probes first; errors are explained, never fabricated as success. Local history/log data is not included in diagnostic exports. Interfaces are small enough to move Git/AI into a separate app later.

Test synthetic image operations and mock capture failures, not private desktop captures.
3. Clipboard: event-only WM_CLIPBOARDUPDATE subscription on opt-in, pause unsubscribes. 4. Git: user-added local repositories only; roots depth/path/count bounded. 6. AI Limits: Manual provider works without logs or assumed caps. Verify/document Claude/Codex log formats/paths; read only explicitly enabled allowlisted log roots, exclude credential/token/config files, sanitized fixtures. Every report states built/commands and results/measured RAM+CPU/known gaps/next step. A working shell or fixture is not completion of a module. No blanket pass from mock tests.
