# Black Notch control center evidence

Verification date: 30 October 2026. Development and captures were performed in the user's Tidlet folder. No Git write, machine-setting change, real process termination or real playback command was performed. This is the explicitly approved media/focus UI extension, not M4-M7 acceptance.

## Build and tests

`dotnet restore TidletMonitor.sln --locked-mode` and `dotnet build TidletMonitor.sln -c Release --no-restore -m:1 -p:UseSharedCompilation=false -nodeReuse:false` passed with zero warnings/errors. The normal Release executable is under src/IsletMonitor/bin/Release/net8.0-windows.

`dotnet test TidletMonitor.sln -c Release --no-build --no-restore --logger trx --results-directory TestResults/notch-final-x64` passed 92 tests (50 Core, 18 Shell, 24 Windows). Repeating with `-- RunConfiguration.TargetPlatform=x86` and a separate `TestResults/notch-final-x86` directory also passed 92 tests. The actual x86 native ABI test logged pointer size 4; the VSTest launcher itself still prints x64. Both result guards accepted three nonempty passing suites. Playback/control-executor tests use fakes only. Timer tests cover pause/resume, long invisible intervals, completion/restart, reset and invalid input. Media tests cover lazy creation, denial, disabled/stale tokens, failure, single-flight requests and native click routing to a mock executor. The compact home starts no disk polling.

Native smoke results: smoke-control-center.ps1 passed two compact themes and a full dark CPU page, each with natural exit, zero real playback commands, no WPF initialization and zero timers after exit. The real unpackaged media manager returned NoSession rather than a permission/API failure. smoke-shell.ps1 -IncludeFullscreenFixture passed seven cases and captured nine style/state combinations, including owned borderless fullscreen hide/resume. smoke-dashboard.ps1 captured all sixteen full dashboard pages/themes. The measurement harness passed 24 checks. Hosted GitHub Actions was updated but not executed from this session.

The original Release build was briefly blocked by the user's old running app. A temporary build within artifacts/notch-control-center was tested while waiting; after the user closed the old app, the normal Release output was rebuilt and verified. A smoke-shell invocation with an unsupported OutputDirectory parameter failed before launching; the corrected invocation above passed. Sandbox script authorization failures were retried with the normal non-admin desktop token. No execution policy or security setting was changed.

## Visual inspection

The PNGs in frames are actual final native render-buffer captures from this app, not desktop screenshots and not concept art. Both compact themes and the full dark CPU view were inspected. Exact card pixels were #080809 in dark mode and #FFFFFF in light mode. The scanned three frames contain zero green-dominant pixels. The root uses #0D0C0F at the renderer's existing 248/255 opacity; compositing can therefore slightly alter on-screen root pixels. The white theme remains unchanged.

## Measurements

Two complete feature measurements were collected sequentially; raw samples, summaries, native probe reports and nine binary hashes are retained per scenario. Expanded Notch: 301.001441 seconds, 302 samples, 71.04512 MB peak, 63.804911 MB mean, 0.261496879% machine CPU / 2.091975035% core-equivalent: PASS. Post-expansion collapsed Notch: 300.003635 seconds, 301 samples, 68.837376 MB peak, 65.447167 MB mean, 0.085936459% machine CPU / 0.687491670% core-equivalent: FAIL (memory). The lifetime peak 79.413248 MB includes earlier expansion/style exercise. Raw CSV recomputation reproduced both results, and native lifecycle checks passed. The latter trial intentionally exercises styles/states before the warmup; it is a post-expansion trial, not a pure cold collapsed trial. The final state was Notch/Collapsed; both media assemblies remained loaded. Implementation is stopped for budget review; see docs/MEDIA_MEMORY_PROPOSAL.md. No new hidden 300-second trial was started after this failure. Short cold/hidden diagnostics are explicitly DiagnosticOnly. The expanded home includes both loaded media assemblies, even though no player was active. No forced collection, working-set trim, profiler or helper process is used. The measuring PowerShell process is an external observer; its CPU cost is reported separately by the existing harness. Other ordinary desktop applications remain running, so this is not an isolated laboratory machine.

## Limits

Real music commands were not issued. An active player, metadata changes, browser/player-specific support, denied-policy behavior on physical machines, and old Windows 10 runtime fallback still require real-device validation. Unit tests cover the mock denial/failure/control boundaries. The focus timer is session-only and has no alarm/notification. The native panel's new controls are pointer-driven; expanded keyboard/accessibility navigation remains a gap. Two physical monitors at different DPI, exclusive D3D fullscreen, Windows 10 hardware and a separate 8 GB PC scenario were not validated. Existing GPU/advanced-sensor absence, unfinished physical-adapter network filtering and broader M2/M3 acceptance gaps remain unchanged. SDK redistribution terms/notices must be confirmed before release packaging, as recorded in DECISIONS.md.
