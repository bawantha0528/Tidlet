## Shell and lifecycle

| Contract | Documented fact and implementation consequence | Official source |
|---|---|---|
| Window styles | WS_EX_NOACTIVATE prevents normal activation; WS_EX_TOOLWINDOW excludes taskbar/Alt+Tab. Use these for the ambient island; settings/confirmations have a normal accessible window. Verify live HWND/foreground behavior separately. | [Extended styles](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles) |
| Transparency | AllowsTransparency requires WindowStyle=None. This permits irregular shapes, not a guaranteed memory/CPU budget. | [WPF AllowsTransparency](https://learn.microsoft.com/en-us/dotnet/api/system.windows.window.allowstransparency?view=windowsdesktop-8.0) |
| Layered click-through | Layered WS_EX_TRANSPARENT passes mouse events underneath. WPF hit-test flags alone are insufficient to prove cross-process behavior. | [Window features / layered windows](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features) |
| Hit testing | HTTRANSPARENT forwards hit testing to same-thread windows; it is not a universal cross-process input pass-through guarantee. | [WM_NCHITTEST](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-nchittest) |
| Layered surface size | Layered updates can update the whole surface; keep the HWND close to actual content. Do not allocate a transparent screen-sized overlay. | [UpdateLayeredWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-updatelayeredwindow) |
| DPI | Use PMv2, handle WM_DPICHANGED and deliberately convert physical pixels/WPF DIP. Test signed coordinates and mixed monitor scale factors. | [High DPI development](https://learn.microsoft.com/en-us/windows/win32/hidpi/high-dpi-desktop-application-development-on-windows) |
| Fullscreen signal | SHQueryUserNotificationState exposes notification policy; fullscreen transitions do not generate a dedicated notification. Busy/exclusive-D3D states inform suppression but do not prove exhaustive per-monitor fullscreen detection. | [SHQueryUserNotificationState](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shqueryusernotificationstate), [state values](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ne-shellapi-query_user_notification_state) |
| Demand rendering | Leaving CompositionTarget.Rendering attached causes continuous animation; detach at rest/hidden. Prefer finite clocks and changed-value invalidation. | [WPF other performance recommendations](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/optimizing-performance-other-recommendations) |
| Layout | Layout work has cost; reuse/update existing transforms rather than rebuilding visual/layout objects each sample. | [WPF layout/design performance](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/advanced/optimizing-performance-layout-and-design) |
| Power | RegisterPowerSettingNotification yields WM_POWERBROADCAST events. User-mode apps should use session display status; no lid notification may arrive until a lid exists. Missing is unknown. | [Power GUIDs](https://learn.microsoft.com/en-us/windows/win32/power/power-setting-guids), [registration](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerpowersettingnotification) |

## Tier 1 metrics

| Capability | Documented source and semantics | Failure/uncertainty policy |
|---|---|---|
| CPU | [GetSystemTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getsystemtimes): kernel includes idle; 100 ns times. CPU = 100×(delta kernel + delta user − delta idle)/(delta kernel + delta user). | First/reset/failed observations are unavailable/warming up. >64-processor machines expose only the caller's primary processor group: `TODO(verify)` group-aware fallback; no mislabeled whole-machine reading. |
| RAM | [GlobalMemoryStatusEx](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-globalmemorystatusex): initialize length; physical totals/available describe volatile system memory. | Reject zero total, available>total or failure. Physical usage is not a standalone slow-PC diagnosis. |
| PDH lifecycle | [PdhAddEnglishCounterW](https://learn.microsoft.com/en-us/windows/win32/api/pdh/nf-pdh-pdhaddenglishcounterw) accepts English paths. [Formatted counter values](https://learn.microsoft.com/en-us/windows/win32/api/pdh/nf-pdh-pdhgetformattedcountervalue) need return status and CStatus checks. | Query creation does not prove instance support. Rate counters need warmup. Enumerate/probe, handle disappearing instances, release handles. |
| Disk | [Official PhysicalDisk counter schema](https://learn.microsoft.com/en-us/previous-versions/aa394308(v=vs.85)) describes byte rates/timing. | Pick per-disk or total, never sum both. `TODO(verify)`: selected busy/activity metric, exact English counter paths and RAID/Storage Spaces semantics. Do not enable counters/change settings. |
| Interface rates | [GetIfTable2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-getiftable2) returns allocated physical/logical interface table; free with FreeMibTable. [MIB_IF_ROW2](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/ns-netioapi-mib_if_row2) supplies 64-bit octets, LUID/state/type/flags. | Stable LUID + monotonic deltas, reset on reconnect/sleep. Metadata filters and topology tests; virtual names alone are insufficient. `TODO(verify)`: external Hyper-V switch, teaming/bridge behavior and a complete physical-uplink policy. |
| ICMP | [Ping.SendPingAsync](https://learn.microsoft.com/en-us/dotnet/api/system.net.networkinformation.ping.sendpingasync?view=net-8.0) provides async echo. | One bounded request, no hidden polling, visible optional target. Blocked/timeout ICMP doesn't prove internet outage. Jitter's chosen formula is a product definition, not an API claim. |
| WLAN | [Wi-Fi access/privacy changes](https://learn.microsoft.com/en-us/windows/win32/nativewifi/wi-fi-access-location-changes) describe location consent for sensitive current-connection information; queries can prompt/deny. | Avoid surprise startup prompts/scans. `TODO(verify)`: cross-version signal-only query path without BSSID access; exact structures, access checks and minimum builds. Permission-required values stay unavailable until user action. |
| Battery status | [Native battery information](https://learn.microsoft.com/en-us/windows/win32/power/battery-information) documents the Windows battery interfaces. | Basic percentage/status and detailed rate/health are separate probes. `TODO(verify)`: standard-user native enumeration, IOCTL structures/units/sentinels and aggregate/multiple-battery semantics before selecting final implementation. |
| Rich battery fields | [Battery](https://learn.microsoft.com/en-us/uwp/api/windows.devices.power.battery) supports aggregate/individual reports. [BatteryReport](https://learn.microsoft.com/en-us/uwp/api/windows.devices.power.batteryreport) fields may be nullable; [charge rate](https://learn.microsoft.com/en-us/uwp/api/windows.devices.power.batteryreport.chargerateinmilliwatts) is negative during discharge. | No null-to-zero conversion. Prefer native route if equivalent; WinRT .NET 8 projection/dependency impact is `TODO(verify)`, not an approved package. Full/design health requires matching valid units. |
| Battery fallback | [powercfg command reference](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/powercfg-command-line-options) documents /batteryreport as historical reporting. | On-demand historical data only; no live-rate polling or frequent command spawning. Test command/parse paths with mocks and sanitized fixtures; do not run commands during current planning. |
| GPU | [Microsoft GPU design](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/) describes WDDM 2.0+ adapter/engine telemetry and busiest-engine overall utilization. [DXGI_ADAPTER_DESC2](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/ns-dxgi1_2-dxgi_adapter_desc2) supplies adapter LUID/description. | Keep hybrid adapters separate. `TODO(verify)`: exact GPU PDH names, instance grammar/LUID mapping, physical-engine grouping, process summation and hotplug. Do not guess correlation from a string pattern or sum independent engines. |
| Process reads | [Process security/access](https://learn.microsoft.com/en-us/windows/win32/procthread/process-security-and-access-rights) distinguishes query rights from terminate rights; protected targets deny access. | Minimal rights; fail per process, release handles, identity PID+creation time. `TODO(verify)`: exact GetProcessTimes/working-set APIs and normalization. |
| Process action | [TerminateProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-terminateprocess) is unconditional/asynchronous and may damage application-maintained state. | Explicit unsaved-work warning, identity recheck, unsafe-target blocklist and no silent elevation. All testing uses a mock executor. Never terminate real processes to validate this project. |
| Coarse thermal zone | [Windows thermal design](https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/design-guide) discusses thermal-zone units but does not establish a universal public user-mode CPU temperature API. | `TODO(verify)`: current official contract/access/units for MSAcpi_ThermalZoneTemperature and a dependency-free query path. Optional, no admin, no System.Management package without approval. Label “ACPI thermal zone,” never CPU core/package. Unsupported is expected on many PCs. |

## Measurement and tooling

- [Process.WorkingSet64](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.workingset64?view=net-8.0): resident working set is distinct from heap/private bytes. Refresh before observing; record sampled max and startup/lifetime peak separately.
- [Environment.ProcessorCount](https://learn.microsoft.com/en-us/dotnet/api/system.environment.processorcount?view=net-8.0): affinity/CPU limits can affect available processor count. Report CPU seconds, core-equivalent percentage, normalized percentage and denominator.
- [dotnet test](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-test): .NET 8 uses VSTest; .NET 10 runner-selection behavior must not leak into an unpinned .NET 8 repository.
- [MSTest execution](https://learn.microsoft.com/en-us/dotnet/core/testing/unit-testing-mstest-running-tests): supports VSTest as well as MTP. Exact restored package compatibility still needs build/test validation.
- [CLI telemetry opt-out](https://learn.microsoft.com/en-us/dotnet/core/tools/telemetry) and [MTP telemetry opt-out](https://learn.microsoft.com/en-us/dotnet/core/testing/microsoft-testing-platform-telemetry): use DOTNET_CLI_TELEMETRY_OPTOUT=1 and TESTINGPLATFORM_TELEMETRY_OPTOUT=1 in build/test child-process environment, no persistent machine changes.
- [Current .NET support policy](https://dotnet.microsoft.com/en-us/platform/support/policy): .NET 8 ends support 10 November 2026. Keep requested target and record the imminent lifecycle risk.
- [Microsoft.NET.Test.Sdk official package](https://www.nuget.org/packages/Microsoft.NET.Test.Sdk/): 18.11.0, .NET 8 target, MIT.
- [MSTest.TestFramework official package](https://www.nuget.org/packages/MSTest.TestFramework/): 4.5.2, .NET 8 target, MIT.
- [MSTest.TestAdapter official package](https://www.nuget.org/packages/MSTest.TestAdapter/): 4.5.2, .NET 8 target, MIT.

The [v0.9.5 release](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/releases/tag/v0.9.5) includes the transition; the [official release list](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/releases) currently shows v0.9.6 with PawnIO module work.

This is research only. Do not add LHM, PawnIO, a helper, driver assets or elevation during M0–M3. Never bundle WinRing0. Before M4, reverify selected release/target frameworks, driver license/signature/install requirements, transitive graph, explicit opt-in and helper crash isolation. No sensor or driver has been tested here.

Current Windows 10 servicing coverage is edition/lifecycle-dependent; functional compatibility tests do not imply Microsoft support for every Windows 10 edition/build. No x86 build or runtime test has run.
