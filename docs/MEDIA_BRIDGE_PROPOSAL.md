# Native media bridge: proposal after worker measurement

Status: approved on 30 October 2026; native bridge implemented and under validation. The following measured failure explains the historical proposal. The user-approved worker is implemented and retained, but its expanded aggregate memory gate failed. No budget was relaxed and no commit was made.

The stable held-input Notch trial measured 300.975004 seconds / 302 samples. Parent plus one continuously active worker peaked at 112.418816 MB (mean 104.929158 MB), exceeding 100 MB by 12.418816 MB. Combined CPU was 0.275147434% of the eight-logical-processor machine / 2.201179473% of one core. Raw parent/worker CSV recomputation reproduced the failure. Native lifecycle checks passed: one worker, zero main-process media/WPF assemblies, no WPF in the worker, unchanged Notch/Expanded history, natural worker exit and zero remaining native timers. The input hold was a timed diagnostic flag; real pointer/fullscreen checks continued and normal launches stay interactive. No forced GC or trimming was used.

The worker successfully isolates the SDK, but the sum of two process working sets exceeds the unchanged expanded budget. Shared runtime pages still count in that sum; private bytes are not a substitute for the agreed working-set limit. This proposal is therefore to remove the second process from normal media access, not to change the renderer or reinterpret its costs.

## Recommended next implementation

Keep the UI, portable focus/media contracts, validation and failure states. Implement a narrow native WinRT/COM provider for the same Windows media-session APIs, and stop launching the worker in normal use. Do not initialize the large managed SDK projection in the ambient process. Preserve the measured prototype/evidence for review; decide archive/removal of its SDK-dependent code separately. No new NuGet package, driver, admin rights, service, system-setting change or M4 hardware helper is proposed.

Before feature code: verify the exact activation and async interfaces, GUIDs, vtable order, HRESULT signatures and HSTRING/reference ownership against official Windows SDK metadata/docs; mark unresolved details TODO(verify). Do not guess generic async IIDs or copy a third-party snippet. Keep native calls behind a bounded asynchronous provider boundary. Validate every optional/invalid reading and session identity before dispatch; release every owned native reference. An unsupported or failing provider must give a reason instead of launching the over-budget worker silently.

Test ABI/lifetime/error paths on both bitnesses, including fake native executors for every automated playback command, real read-only manager/no-player probes, stale sessions, denied permission, pending-operation teardown and repeated open/close resource counts. Live player actions remain unverified until actually exercised with the user's authorization. Then repeat aggregate 300-second expanded, post-expansion collapsed and hidden gates. Require zero workers and zero loaded SDK projection/runtime assemblies in the ambient path. Keep 60 MB collapsed / 100 MB expanded, <1% collapsed average CPU and approximately-zero hidden CPU unchanged. Do not claim this alternative meets those gates before measuring it.

The remaining frozen-worker observations are recorded in docs/evidence/media-worker/README.md: collapsed/style exercise 56.659968 MB / 0.018169001% machine CPU; hidden 37.908480 MB / 0.000651022%. Each ran at least 300 seconds. Qualification: the style exercise canceled its worker before SDK initialization; it is not a full integrated after-using-loaded-media gate. Separate read-only workers did load the SDK and exit normally. These do not change the expanded failure. The user subsequently approved this proposal; current bridge evidence is tracked under docs/evidence/native-bridge. M4-M7 remain deferred; all Git operations remain manual.
